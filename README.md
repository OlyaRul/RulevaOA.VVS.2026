## [ДЗ3](DZ3/) - Лабиринт. 
Задача: реализовать игру "Лабиринт", используя списки  
Игра, в которой цель игрока - найти выход из лабиринта, для чего нужно перемещаться по нему, искать предметы и сражаться с монстрами  
Использована библиотека copy для создания глубокой копии инвентаря (для возможности сбросить изменения без сохранения), библиотека random - для генерации случайных чисел 
Методы списков использованы для хранения карты лабиринта и инвентаря. Методы списков (append, pop, remove, extend, sort, index) - использованы для работы с инвентарем  

В моем решении существует несколько типов наполнения комнат:
 - сундуки (в них можно положить что-либо или забрать себе. При первом открытии сундука в нем лежат какие-то предметы, при повторном открытии они остаются такими же, какими были в прошлый раз)
 - ключ (без него нельзя открыть выход, наличие клетки с ключом гарантировано)
 - выход (конечная клетка маршрута, если при попадании в нее у игрока в инвентаре есть ключ - то игра окончена)
 - портал (переводит игрока в случайную клетку маршрута)
 - монстр (Монстр обладает определенной силой (случайное число), в зависимости от соотношения силы монстра и наносимого урона определяется итог боя. По итогам монстр может или убежать (клетка становится пустой), или остаться в комнате, но отпустить игрока, или победить игрока, в таком случае игра завершится. Игрок может выбрать 2 предмета из инвентаря для усиления)
 - пустые клетки (в них ничего не происходит)
Также игрок может взаимодейстовать с инвентарем. Все предметы в инвентаре - объекты класса thing, обладает определенными характеристиками. Сам по себе инвентарь - ограниченный по вместимости рюкзак (до 15 предметов) с возможностью поиска по названию, просмотра характеристик, сортировки (по алфавиту, урону, защите, здоровью, знаниям) и отката изменений до сохранения, с возможностью создания нового снаряжения из добытых материалов (камня и железа) с помощью инструментов при наличии достаточного уровня знаний (`kp >= 50`), а также улучшения оружия, брони и инструментов до «Супер»-версий.


Движение игрока по полю осуществляется с помощью клавиш `w`, `a`, `s`, `d` (вверх, влево, вниз, вправо), `z` — открыть меню управления инвентарём

7. Результаты: сохранение обработанного датасета в [titanic_processed.csv](DZ4/titanic_processed.csv) и итоговой сводной статистики в [titanic_statistics.csv](DZ4/titanic_statistics.csv).



## [ДЗ5](DZ5/) - GUI. 
Задача: разработать графический интерфейс на Tkinter и PyQt  
В папке представлена реализация to do - листа на [TKinter](DZ5/lr1.py) и [PyQt](DZ5/lr2.py)  - приложение для повседневного планирования, где можно добавлять и удалять задачи, распределять их по сложности
    
### TKinter ###
- Собрано главное окно с полем ввода, переключателями приоритета («Срочный», «Важный», «Обычный») и списком задач, разбитым по категориям.
- Защита от случайных ошибок: программа не даёт создать задачу короче 5 символов или не выбрать приоритет
- Сделано удаление задачи по клику с всплывающим окном подтверждения.
- Интерфейс оформлен в единой тёплой цветовой гамме и добавлено всплывающее окно обратной связи, которое появляется через каждые 5 добавленных задач.

Приложение реализовано с помощью встроенной графической библиотеки **tkinter** и её стилизованного модуля **ttk**.
Для отображения задач по категориям использовали древовидный виджет `ttk.Treeview`, для выбора срочности — `Radiobutton` с общей переменной `IntVar`, а для предупреждений и подтверждений — отдельные всплывающие окна `Toplevel`.Внешний вид настроен через `ttk.Style`, прописав цвета, шрифты и реакцию кнопок на наведение мыши (`.map()`)

### PyQt6 ### 
Удобное приложение с тёмной темой, где пользователь может пройти авторизацию, добавлять новые задачи с выбором срочности, отмечать выполненные дела и удалять лишние.

- Цепочка окон для входа в систему: приветственное окно, форма регистрации и окно авторизации с выводом сообщений об ошибках при неверном логине или пароле. (основное окно построили на `QMainWindow`, диалоги и формы входа — на `QDialog` и `QWidget`)
- Главное окно со строкой ввода, переключателями приоритета («Срочный», «Важный», «Обычный») и списком задач, в котором элементы автоматически выстраиваются по важности
- Статус выполнения у каждой задачи и удаление по двойному клику через диалоговое окно подтверждения
- Всплывающие предупреждения (если не выбран приоритет или введено меньше 5 символов), окно обратной связи каждые 5 задач
- Единая темная тема оформления
Для аккуратного расположения элементов использованы компоновщики `QVBoxLayout`, `QHBoxLayout` и `QFormLayout`. Список задач реализован как `QListWidget` и `QListWidgetItem` со встроенными чекбоксами (`CheckState`), а порядок сортировки по приоритетам организован с помощью массива последних индексов в каждой категории `last_indexes`.  Тёмный стиль ко всем окнам применен с помощью библиотеки qdarktheme (`qdarktheme.load_stylesheet("dark")`).


## [ДЗ6](DZ5/lr2.py) - База данных. 
Задача: привязать базу данных к интерфейсу из дз5
Так как дз 5 и 6 связаны, дз 6 реализовано в том же файле, что и ДЗ5, (интерфейс на PyQt). В этом файле помимо интерфейса реализовано взаимодействие с базой данных, а именно хранение учетных записей пользователей. 

Локальная база данных `data.db` состоит из двух связанных таблиц: `people` (для хранения логинов и паролей) и `tasks` (для хранения текста задач, их приоритета, статуса выполнения и привязки к владельцу).
В моем решении настроена регистрация и вход: проверка уникальности имени пользователя и сверка пароля по базе, реализована автоматическая синхронизация списка задач с базой: при запуске подгружаются только задачи текущего пользователя, а любое добавление, удаление или смена галочки сразу сохраняются в бд.  
  
С помощью встроенного модуля **sqlite3** созданы таблицы (SQL-запросы `CREATE TABLE IF NOT EXISTS`), связанные через внешний ключ `FOREIGN KEY (user_id) REFERENCES people(id)`. Для регистрации и проверки пароля использована выборку `SELECT` и вставку `INSERT` с параметризованными запросами (`?`) для безопасной подстановки данных (предотвращения SQL-инъекций). Изменения в задачах обрабатываются через события интерфейса: при добавлении задачи выполняется `INSERT` (и сохраняется `cursor.lastrowid` внутрь элемента списка), при нажатии на чекбокс — `UPDATE`, а при удалении — `DELETE` с обязательным подтверждением транзакции через `con.commit()`.
